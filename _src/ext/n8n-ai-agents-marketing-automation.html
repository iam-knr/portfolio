Core n8n ideas you need on day one

  • Node. One step. A trigger node starts the flow. Other nodes read, change or send data.
  • Item. A piece of data moving through the flow, such as one lead. Most nodes run once per item.
  • Expression. A small snippet inside a field that pulls data from an earlier node, for example the lead's phone number.
  • Credential. A saved key or login. Store it once, and reuse it in many nodes.
  • Execution. One run of the flow. n8n keeps a history so you can open any past run and see the data at each step.
  • Error workflow. A second flow that runs when the first one fails. Use it to alert yourself.

SOP: Build the lead response flow

This builds on workflow 1 above. I show it as a procedure so a teammate can follow it without you.

SOP 6: Lead response in n8n Owner: automation builder. Time: 1 to 2 days with testing

  1. Trigger. Add a webhook or a form trigger. Send one test lead and open the output to see the field names.
  2. Clean the data. Add a step that trims spaces, formats the phone number with the country code, and lowercases the email.
  3. Check duplicates. Search the CRM by phone and email. If found, branch to a "tag existing lead" step and stop.
  4. Classify. Add the AI Agent node. System message: label intent as ready, researching or not a fit, and quote the supporting answer.
  5. Create the record. Write the lead and the label to the CRM.
  6. Draft the message. Fill a pre-approved template. Do not let the model invent offers or prices.
  7. Approval step. Send the draft to a team chat with approve and edit buttons. Wait for the answer.
  8. Send. After approval, send through your WhatsApp or email provider. Log the message id.
  9. Alert on silence. A second branch waits 30 minutes. If no human follow up appears, notify the owner.
  10. Error workflow. Create a flow that posts to your chat on any failed run with the lead id and the failing node.
  11. Test. Run twenty sample leads, including a duplicate, a bad phone number and an empty form. Fix what breaks.
Output: one flow, one error flow, one test sheet. Go live in draft mode. Consider auto-send only after two weeks of clean approvals.

SOP: Run n8n yourself

You can use the paid cloud service or host it yourself. If you host it, treat it like any small production service.

SOP 7: Self-hosting basics Owner: technical lead. Time: half a day, then monthly upkeep

  1. Pick a server. A small cloud server is enough to start. Check n8n's docs for current minimum sizes.
  2. Use the official install route. The docs describe a container setup. Follow the current steps instead of old blog posts.
  3. Add a domain and HTTPS. Webhooks need a public address. Always use HTTPS.
  4. Lock it down. Strong owner password, two step login where offered, no public sign up.
  5. Back up. Schedule a daily backup of the database and the encryption key. Test a restore once.
  6. Update on a schedule. Read release notes, update monthly, and keep one version of rollback.
  7. Monitor. A simple uptime check that messages you if the server is down.
  8. Write it down. One page: where it runs, who has access, how to restore.
Output: a running instance with backups and a one page runbook. If nobody on your team can own this, use the cloud plan instead.

Reading the execution log

When something looks wrong, open the execution and work from the failing node backwards.

  1. Find the red node. Read the error text. Most errors say a field was empty or a key was refused.
  2. Click the node before it. Look at its output. Was the data you expected there?
  3. Compare with a good run. Differences in the input usually explain the failure.
  4. Fix the cause, then re-run with the saved data instead of waiting for a new lead.

Prompt template for the agent node

System message template Role: You review lead form answers for [business]. You do not talk to the customer.
Task: Label the lead as ready, researching or not a fit.
Rules: Quote the exact answer that supports the label. If the form is empty or unclear, label researching and say what is missing. Never invent facts. Never mention prices.
Output: JSON with label, reason and quote.

Ask for a fixed output shape such as JSON. The next node can then read the label directly, with no guessing.

Cost and speed notes

  • Keep the prompt short and send only the fields the agent needs. Smaller inputs cost less and run faster.
  • Use a smaller, cheaper model for simple labeling. Keep the larger model for tasks that need real reasoning.
  • Cache lookups that rarely change, such as a price list.
  • Watch the usage page of your model provider weekly for the first month.
