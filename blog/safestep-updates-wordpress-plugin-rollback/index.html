SafeStep Updates: A Free WordPress Plugin That Rolls Back Bad Plugin Updates

Updates fix sites, and sometimes they break them. I built SafeStep so the fear of a bad update stops being the reason you skip updates.

By Kailas (KNR) Nath RPublished 19 Nov 20265 min read
Short answer

SafeStep Updates is a free WordPress plugin that makes a copy of a plugin before every update, checks your home page, login page and any pages you list right after, and restores the old version if the update caused a new server error or PHP fatal. It covers manual, automatic and WP-CLI updates. It needs WordPress 6.0 or newer and PHP 7.4 or newer. It is not a backup plugin.

The problem: updates fix sites and break them

Every WordPress site owner knows the choice. Update a plugin and risk a broken site. Skip it and leave a known problem unfixed.

Many people put updates off because of the fear. That leaves security fixes sitting there. Others update and then find out three days later, from a customer, that the checkout stopped working.

Three things go wrong most often:

  1. You put it off. Skipped updates leave known problems unfixed.
  2. A bad update lands. A bug, or a clash with another plugin, and visitors see an error page.
  3. You find out late. Nobody watches the site at 3 a.m. It stays down until someone notices.

There is a cost for marketers too. If an ad campaign is live and the landing page returns an error, you pay for clicks that land on nothing. I check tracking before I touch a budget for the same reason. A site that is down is the same kind of leak.

How SafeStep works

WordPress installs the update the way it always does. SafeStep adds a copy before it, a check after it, and a way back. There are four steps.

  1. Snapshot. The plugin's current files are copied into a protected folder just before they are replaced.
  2. Install. WordPress installs the update as normal. Your workflow does not change.
  3. Check. Your home page, login page and any pages you list are requested. A server error or a PHP fatal counts as a failure. Problems that were already there are ignored.
  4. Keep or roll back. If the site is healthy, nothing more happens. If it is broken, the old version returns, you get an email, and the bad version is held.

The old version comes back before most visitors notice. By the time you read the email, the site is already on the working version.

What you get

  • Snapshot before every update. It covers the Plugins screen, the Updates screen, bulk updates, automatic updates and WP-CLI. You choose how many past versions to keep.
  • A health check afterwards. The home page, the login page and pages you add, such as /shop/ or /checkout/. It compares with how the site behaved before the update.
  • Automatic rollback. When an update causes a new failure, the previous version is restored.
  • Version hold. A version that broke your site is not installed automatically again. You release the hold when a fix ships.
  • Email alerts. You know the moment something is rolled back.
  • Restore and log. Restore any snapshot in one click and see a history of every update, rollback and restore.

Everything sits in one screen in WordPress, under Tools, then SafeStep. There you set auto-updates, exclude plugins, add pages like /checkout/, and set the alert email.

SafeStep compared with WordPress itself

WordPress 6.6 and later already rolls back an automatic update that causes a fatal error. That is good. SafeStep covers what core does not.

  • Updates you click yourself, bulk updates and WP-CLI. Core does not roll these back. SafeStep takes a snapshot, checks and rolls back.
  • HTTP 5xx errors without a fatal. Core does not check for them. SafeStep detects them.
  • Keeping older versions. Core does not. SafeStep lets you choose how many to keep.
  • Not retrying a version that failed. Core does not. SafeStep holds the version.
  • Email when a rollback happens. Core does not send one. SafeStep does.

For an automatic update that causes a PHP fatal error, both roll back.

What SafeStep does not do

I would rather say this plainly than have you find out later.

  • It is not a backup plugin. It stores plugin files only. It does not back up your database, uploads or themes. Keep real backups too.
  • It only handles plugins. It does not update themes or WordPress core.
  • It cannot see every breakage. It looks for server errors and PHP fatals on the pages it checks. It will not notice a checkout that quietly stops working. Add your key pages to the list.
  • Single sites for now. Multisite is not supported yet.

How to install SafeStep

You need WordPress 6.0 or newer and PHP 7.4 or newer. The plugin is free and uses the GPL licence.

  1. Download the zip from safestep.iamknr.in (version 0.2.0 at the time of writing).
  2. In WordPress go to Plugins, Add New, Upload Plugin, choose the zip and activate it.
  3. Manual updates are protected straight away. Open Tools, then SafeStep, to turn on auto-updates and add the pages you care about.

Frequently asked questions

What is SafeStep Updates?

SafeStep Updates is a free WordPress plugin that snapshots every plugin update, checks your site afterwards and rolls back automatically if the update breaks it.

Does SafeStep cost anything?

It is free and released under the GPL licence.

Which updates does it protect?

Manual updates from the Plugins or Updates screen, bulk updates, automatic updates and WP-CLI updates.

What counts as a failure?

A server error or a PHP fatal on the pages it checks. Those are your home page, login page and any pages you add. Problems that already existed before the update are ignored.

Is SafeStep a backup plugin?

No. It stores plugin files only, not your database, uploads or themes. Keep your usual backups.

Does WordPress already roll back bad updates?

WordPress 6.6 and later rolls back an automatic update that causes a fatal error. It does not do that for updates you run yourself, in bulk or with WP-CLI. SafeStep covers those.

What versions does it need?

WordPress 6.0 or newer and PHP 7.4 or newer. Multisite is not supported yet.
